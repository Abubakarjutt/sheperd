# rewire v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A thin but complete anti-slop factory slice for TypeScript repos: `rewire run "<task>"` compiles a contract, writes frozen failing tests, implements in a sandbox, passes hard-block gates and a verified 3-reviewer panel, and produces a local branch plus an evidence report — or escalates, never shipping unverified code.

**Architecture:** A pnpm TypeScript monorepo (orchestrator, Pi-inspired agent loop, providers, gates, reviewers, CLI) plus one Rust binary `rewire-sandbox` that is the only enforcement point for file writes and command execution (Seatbelt on macOS, bubblewrap on Linux). Each pipeline stage runs a fresh agent-loop instance with its own tool set, capability profile and model; stages communicate only through typed artifacts (Contract, FrozenTestManifest, GateResult, Finding).

**Tech Stack:** Node ≥ 22.19, TypeScript 5 (strict), pnpm workspaces, vitest, zod, biome, `@anthropic-ai/sdk`, `openai` (also used for Ollama's `/v1`), `smol-toml`, `picomatch`, `shell-quote`; Rust stable (edition 2021), `clap`, `serde`/`serde_json`, `globset`, `anyhow`. External gate tools: `tsc`, the repo's linter, vitest/jest, `semgrep`, `gitleaks`, `npm audit`, `rg`.

**Spec:** `docs/DESIGN-DECISIONS.md` (decisions #1–#27 plus the v0.1 roadmap) and `docs/research/harness-comparison.md` (Phase 0 evidence). Read both before starting.

## Global Constraints

- License: Apache-2.0 for every package and crate. Add a `LICENSE` file and an SPDX `license` field to each `package.json` / `Cargo.toml`.
- Clean-room: no code, prompt, or structure copied from Claude Code's bundled source. Pi (MIT) and Codex (Apache-2.0) may be adapted, and each such file must say so in a header comment.
- Hard-block categories (never shippable): `broken`, `fake_verification`, `spec_drift`, `security`, `silent_failure`.
- All nine slop category ids, exactly: `broken`, `fake_verification`, `spec_drift`, `security`, `silent_failure`, `bloat`, `convention_drift`, `maintainability`, `entropy`.
- Fail-closed (#22): any gate, reviewer, hook or plugin that crashes, times out or returns unparseable output is a failed hard block. There is no "no decision" result.
- Enforcement boundary (#21): every file write and every command runs through `rewire-sandbox`. TS-side checks exist only to give earlier, clearer errors.
- Policy layering is tighten-only (#20): repo policy can add gates, raise thresholds and add protected paths. It can never remove or lower anything. A loosening attempt is a load error.
- Credentials (#26): `~/.ssh/**`, `~/.aws/**`, `~/.config/gh/**`, `~/.netrc`, `**/.env*` and `~/Library/Keychains/**` are read-denied in every stage. Network is denied in every stage in v0.1 (single exception: Task 15 audit gate).
- Implementer stage write-denied paths: test globs, `.github/**`, `.rewire/**`, lint/format configs, `tsconfig*.json`, lockfiles, `.git/**`.
- Reviewer findings with no evidence are dropped. Blocking findings need an `upheld` verdict from a verifier whose model family differs from the author's when one is configured. Otherwise the run reports `independence: "same-family"`.
- Ollama is first-class: base URL default `http://localhost:11434`. Chat goes via `/v1/chat/completions`, discovery via native `/api/*`.
- CLI exit codes: `0` verified, `2` escalated to human, `1` internal error.
- Platforms: macOS and Linux. On Windows, `rewire run` refuses to start (exit 1, message `rewire v0.1 requires macOS or Linux`).

## Review Focus

1. **Path escape into protected paths** via `../`, absolute paths, symlinks or a worktree `.git` pointer file. Expected: denied by `rewire-sandbox`, with the canonical target named in the error. Covered by Task 3 `denies_symlink_into_tests` and `denies_dotdot_escape`.
2. **A gate tool that is missing or hangs** (`semgrep` not installed, a test runner that never exits). Expected: the gate fails with `status: "error"` and an install or timeout hint, and the run cannot be verified. Covered by Task 13 `missing_binary_fails_closed` and `timeout_fails_closed`.
3. **The model returns malformed or schema-invalid JSON** for a contract, finding or verdict. Expected: one repair re-prompt containing the zod error, then fail-closed (stage error, then escalation). Never treated as "zero findings". Covered by Task 6 `structured_output_retries_once_then_throws` and Task 16 `reviewer invalid JSON after one repair fails closed`.
4. **The target is not a clean git repo** (not a repo, dirty tree, detached HEAD). Expected: `rewire run` refuses before spending tokens, with a specific message. Covered by Task 5 `refuses_dirty_tree` and `refuses_non_repo`.
5. **Ollama unreachable, or the model lacks tool calling.** Expected: refused at run start with the model name and the failed capability. It never fails mid-run. Covered by Task 7 `rejects_model_without_tools_capability` and `unreachable_server_message`.

### Task 3: `rewire-sandbox` profile, canonical path decisions, fs subcommands

**Files:**
- Create: `Cargo.toml` (workspace), `crates/rewire-sandbox/{Cargo.toml,src/main.rs,src/profile.rs,src/canonical.rs}`
- Test: `crates/rewire-sandbox/tests/path_decisions.rs` (use `assert_cmd`, `tempfile`)

**Interfaces:**
- Produces:
  - **Profile JSON** (shared with TS in Task 5):
    `{ "root": "/abs/worktree", "write": ["src/**"], "writeDeny": ["tests/**"], "readDeny": ["/Users/x/.ssh/**", "**/.env*"], "network": "deny" | "registry", "extraWrite": ["/abs/tmp/rewire-<runId>"] }`.
    Globs are relative to `root` unless absolute. Deny beats allow. Anything outside `root` and `extraWrite` is not writable.
  - CLI:
    - `rewire-sandbox check-path --profile <file> --op read|write <path>` → exit 0 if allowed; exit 3 if denied, with stderr JSON `{"denied":"<canonical>","rule":"<glob>"}`
    - `rewire-sandbox fs-read --profile <file> <path>` → content on stdout
    - `rewire-sandbox fs-write --profile <file> <path>` → content from stdin, atomic write (temp file plus rename, parents created)
  - Exit code `120` = sandbox internal or setup error, malformed profile included (always fail-closed). `3` = policy denial.
- Canonicalization: resolve symlinks for the longest existing ancestor, then append the remaining components lexically. Deny if the result is outside `root`. If `root/.git` is a file (worktree), parse `gitdir:` and add the target directory to `writeDeny` (adapted from Codex `default_read_only_subpaths_for_writable_root`, Apache-2.0).

### Task 4: `rewire-sandbox exec` on macOS and Linux

**Files:**
- Create: `crates/rewire-sandbox/src/exec_macos.rs`, `src/exec_linux.rs`; modify `src/main.rs`
- Test: `crates/rewire-sandbox/tests/exec.rs` (platform-gated with `#[cfg(target_os = …)]`), plus unit tests in both exec modules

**Interfaces:**
- Consumes: `Profile` (Task 3).
- Produces: `rewire-sandbox exec --profile <file> [--timeout-ms N] [--cwd <dir>] -- <cmd> <args…>`. It passes through the child's exit code, stdout and stderr. If the timeout is hit, it kills the process group and exits `124`. If the sandbox can't be applied (for example `bwrap` is missing), it exits `120` and **does not run the command**.
- macOS — `fn build_sbpl(p: &Profile) -> String`:
  - start from `(deny default)`
  - allow `process-exec`, `process-fork`, `signal (target same-sandbox)`, `sysctl-read`, `file-read*` (system-wide)
  - then `(deny file-read* …)` for each `readDeny`
  - `(allow file-write* (subpath …))` for `root` (narrowed by `write` globs translated to `regex` filters) and `extraWrite`
  - then `(deny file-write* …)` for each `writeDeny`, placed after the allows
  - `(deny network*)` when `network: "deny"`; for `"registry"`, `(allow network-outbound (remote tcp "registry.npmjs.org:443"))` plus DNS
  - run via `/usr/bin/sandbox-exec -p <sbpl> -- cmd…`
  - Structure informed by Codex `seatbelt_base_policy.sbpl` (Apache-2.0).
- Linux — `fn build_bwrap_argv(p: &Profile, cmd: &[String]) -> Vec<String>`:
  - `--ro-bind / / --dev /dev --proc /proc --tmpfs /tmp --bind <root> <root>`
  - `--ro-bind <path> <path>` re-applied over each existing match of `writeDeny`, expanded by walking `root` once
  - `--tmpfs <dir>` over each existing readDeny directory, `--ro-bind /dev/null <file>` over each readDeny file
  - `--unshare-net` unless `network: "registry"`
  - `--die-with-parent --new-session`
- Glob expansion happens at exec time, so files created later under a denied glob are covered by the deny-parent-directory rule: for every `writeDeny` glob of the form `<dir>/**`, deny the directory itself, creating it first if missing.

### Task 19: Fix-loop controller with progress, oscillation, re-plan, escalation

**Files:**
- Create: `packages/pipeline/src/fix-loop.ts`
- Test: `packages/pipeline/test/fix-loop.test.ts`

**Interfaces:**
- Consumes: `GateResult`, `Finding`, `fingerprintFinding`, `Policy`.
- Produces:
  - `type RoundState = { round: number; gateFailures: GateResult[]; blocking: Finding[] }`
  - `score(s: RoundState): number` = `10 * s.gateFailures.length + Σ [8,5,3,1][f.severity]` over `s.blocking`
  - `type EscalationReport = { reason: "no_progress" | "oscillation" | "budget" | "dispute" | "clarification_required" | "interrupted" | "stage_error"; tried: string[]; unresolved: Array<GateResult | Finding>; hypothesis: string; question: string }`
  - `type Decision = { kind: "done" } | { kind: "fix"; feedback: string } | { kind: "replan"; history: string } | { kind: "escalate"; reason: EscalationReport["reason"]; unresolved: Array<GateResult|Finding> }`
  - `class FixLoopController { constructor(policy: Policy); record(s: RoundState): Decision; readonly replanned: boolean }`. Rules, checked in order:
    1. `score === 0` → `done`
    2. **oscillation**: a fingerprint (findings) or gate name (gate failures) that was present in an earlier round, absent in a later one, and is present again now
    3. **no_progress**: the score has not been strictly below the best score so far for `policy.noProgressRounds` consecutive rounds
    4. **budget**: `s.round > policy.maxFixRounds`
    5. If any trigger fires: `replan` if not yet replanned (then reset the best score and history window); otherwise `escalate` with that reason.
    6. Otherwise `fix`, with feedback listing gate failures first (name and summary), then findings sorted by severity ascending (`file:lineStart`, category, failureScenario, suggestedFix).
